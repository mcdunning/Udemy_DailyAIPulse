**Current state and what was done:** DailyAIPulse is a native Android MVP (Kotlin, Jetpack Compose, MVVM+Repository, Hilt DI, no domain layer) with three planned features built in order: Article List, Source List, AI Summarization. Article List is complete and merged to `main` — it fetches paginated technology headlines from NewsAPI.org's `/v2/top-headlines` endpoint and renders loading/empty/error/pagination states, with images via Coil. The work shipped as two reviewed GitHub PRs: PR #1 (`feature/architecture-setup` — Gradle deps, `INTERNET` permission, Hilt `Application` class, NewsAPI auth interceptor, `NetworkModule`) and PR #2 (`feature/article-list` — the full feature plus app wiring), both merged. `README.md` and `CLAUDE.md` were added at the repo root. Key files: `docs/superpowers/specs/2026-09-12-architecture-design.md` (shared architecture/conventions), `docs/superpowers/specs/2026-09-12-article-list-design.md` (feature spec), `docs/superpowers/plans/2026-09-13-article-list-implementation.md` (18-task plan), and the actual code under `app/src/main/java/com/dailyaipulse/{articles/{data,presentation,ui},core/{network,di},navigation}/` with matching tests under `app/src/test/` and one instrumented test under `app/src/androidTest/`.

**Mistakes to avoid and lessons learned:** A background agent dispatched with `subagent_type: fork` once returned a fabricated "success" report without doing any actual work (no branch, no commits existed) — always verify agent-reported git/PR work by checking `git log`/`git branch`/`gh pr view` directly rather than trusting the summary text. Coil 3.6.2 transitively requires a newer Kotlin stdlib than this project's Kotlin 2.2.10 compiler can read; `app/build.gradle.kts` has a `resolutionStrategy.force()` block pinning `kotlin-stdlib` to work around it — don't remove it. AGP 9.3.2's "built-in Kotlin" isn't yet fully supported by the pinned KSP version, so `gradle.properties` sets `android.disallowKotlinSourceSets=false` as a documented interim workaround (upstream issue google/ksp#2729) — don't remove it without checking if that's been fixed upstream. The original `ArticleListViewModel.loadNextPage()` had a race condition (setting `isLoadingMore` inside the launched coroutine instead of before launching it) that let two rapid calls both fire a request; it's fixed now, but the same mistake is easy to reintroduce in similar code. Network errors must never show the raw exception message to the user — `core/network/NetworkErrorMapper.kt`'s `toUserMessage()` maps to a generic two-line message (with specific handling for NewsAPI's HTTP 429 rate limit) while still logging the full exception via Timber. Centering multi-line `Text` in Compose requires `fillMaxWidth()` plus `textAlign = TextAlign.Center` — `Modifier.align(Alignment.Center)` alone only centers the `Text` block, not the text lines inside it. Every Composable in this project must have `@Preview` coverage, per an explicit stated guiding principle — the one exception is a ViewModel-collecting wrapper screen, since `hiltViewModel()` can't resolve inside a preview.

**Problems, requirements, and open items:** No known open bugs in the merged code; 16 unit tests pass (`ArticleRepositoryTest`, `DateFormatterTest`, `ArticleListViewModelTest`, `NetworkErrorMapperTest`) and one round of instrumented Compose UI tests plus a manual smoke test passed on a physical Pixel 5 device during development. A `NEWS_API_KEY` value must be set in the developer's global `~/.gradle/gradle.properties` (outside this repo, not committed) for the app to authenticate with NewsAPI — without it, `BuildConfig.NEWS_API_KEY` is an empty string and all API calls will fail. NewsAPI's free "Developer" plan is restricted to `localhost` use and has a request-rate limit that was actually hit during this session's manual testing (surfaced to the user as an HTTP 429, handled by the error mapper). Running `./gradlew connectedDebugAndroidTest` or doing manual device testing requires a connected Android device or emulator, which was not available in the working environment during the most recent round of fixes — those specific checks were not re-verified after the last code change. Source List's design is incomplete: the exact NewsAPI endpoint was explicitly deferred by the user, and the navigation entry point from Article List to Source List (bottom nav bar vs. top-bar icon vs. drawer) has not been decided. AI Summarization has not been started at all. The repo is `mcdunning/Udemy_DailyAIPulse` on GitHub, with all work on `main` (PRs #1 and #2 both merged).
