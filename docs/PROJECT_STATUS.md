# Project Status

Running handoff summary of this project's current state. Read this first when starting a new session — it's meant to be enough, by itself, to work productively without re-deriving context from git history or the full conversation.

## Update rules

Update this document after completing significant work (finishing a feature, merging a PR, resolving a major issue). Replace the content below entirely — don't append a history log. Follow these rules exactly:

- Exactly three paragraphs. No more, no fewer.
- Facts only — no assumptions, theories, or speculation about why something happened or what might be true.
- Written as instructions to another developer, as if this document were the *only* context they would get.
- **Paragraph 1:** what was done and the current state of the project.
- **Paragraph 2:** files updated/created, plus mistakes to avoid and key insights/lessons learned.
- **Paragraph 3:** current problems/errors/open items, and anything else needed to work productively (setup requirements, what's unverified, what's not started).

**Current state and what was done:** DailyAIPulse is a native Android MVP (Kotlin, Jetpack Compose, MVVM+Repository, Hilt DI, no domain layer). Article List (PRs #1, #2) is complete and merged, unchanged since the last update. A navigation shell was added on top of it: a Material 3 bottom navigation bar with two tabs, "Articles" (Article List, start destination) and "Sources" (a blank placeholder screen), resolving the nav-entry-point decision the architecture doc had originally left open (PR #3, merged). Its design content, originally written as a standalone spec file, was subsequently folded directly into `docs/superpowers/specs/2026-09-12-architecture-design.md` (new "## Navigation" section) per reviewer feedback that cross-cutting/shared-architecture decisions belong in the architecture doc itself rather than a new standalone file — the standalone `2026-09-16-navigation-shell-design.md` no longer exists. Source List's real feature (NewsAPI endpoint, data layer, presentation layer, actual list UI) has **not** been started — only its `ui/` package exists, holding the blank placeholder screen.

**Files updated/created, mistakes to avoid, and lessons learned:** `app/src/main/java/com/dailyaipulse/navigation/AppNavigation.kt` (bottom `NavigationBar` wrapping the `NavHost` in a `Scaffold`; a private `navigateToTab` helper using the standard `popUpTo`/`launchSingleTop`/`restoreState` pattern so tab switches don't stack the back stack or lose per-tab state). New file `app/src/main/java/com/dailyaipulse/sources/ui/SourceListScreen.kt` (blank, stateless, `@Preview`-covered — deliberately has no `presentation/`/`data/` packages yet). `app/build.gradle.kts`/`gradle/libs.versions.toml` add `androidx.compose.material:material-icons-core` as an explicit dependency — **lesson:** `material3` does **not** transitively pull in even the base icon set, so any future use of `Icons.*` needs this dependency present; it's already added and documented in the architecture doc's Tech Stack/Resolved Dependency Versions. `.gitignore` now has a blanket `/.idea/` rule (previously only specific sub-files were ignored) — **mistake avoided, not made:** a broad `git add -A` during this session staged `.idea/` config files before they were committed; caught and fixed pre-push by amending the unpushed commit, but the same broad-add habit could easily commit `.idea/` for real next time if the ignore rule weren't now blanket. Three standing process rules from the user are now written into `CLAUDE.md`'s "## Workflow" section (checked into the repo, not just Claude's private memory): (1) a written, approved design doc is required before any code — for an *existing* feature, update that feature's own spec doc rather than creating a new one; a new doc is only for genuinely new feature work; cross-cutting/shared-architecture decisions get folded into the architecture doc itself; (2) all work happens on a feature branch with a PR — never commit directly to `main`; (3) every PR reviewer question gets a reply posted on the PR itself, not just summarized in chat.

**Problems, requirements, and open items:** No known open bugs. `./gradlew :app:compileDebugKotlin` and `./gradlew testDebugUnitTest` both pass; the nav shell was manually verified on a physical Pixel 5 (Articles tab loads real data, bottom bar switches to/highlights the blank Sources placeholder). Setup requirements are unchanged: a `NEWS_API_KEY` in the developer's global `~/.gradle/gradle.properties` is required for the app to authenticate with NewsAPI, and NewsAPI's free plan is `localhost`-only with a rate limit that can surface as an HTTP 429 during testing. Source List's actual design (NewsAPI endpoint, data/presentation layers, real list UI) is still not started and needs its own design spec before implementation, per the mandatory design-doc-first rule (now update the eventual Source List spec doc as that feature gets built, rather than creating scattered new docs for each small change to it). AI Summarization has not been started at all. The repo is `mcdunning/Udemy_DailyAIPulse` on GitHub; PR #5 (branch `chore/document-workflow-rules`) is open and not yet merged as of this update — it carries this very `PROJECT_STATUS.md` edit, the `CLAUDE.md` workflow rules, the architecture-doc Navigation section, and the `.gitignore` fix.
